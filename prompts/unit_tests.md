#### What the function does (analysis)

`calculate_jacobian(u_x, v_y, ds_merge, grid)` in
`src/dbof/utils/native_gradient.py` computes the 2x2 velocity gradient
tensor in geographic (zonal `lambda` / meridional `phi`) coordinates from
model-grid velocity components, following the ECCO-v4 tutorial. Steps:

1. Interpolate `u_x` (U-point, on `i_g`) and `v_y` (V-point, on `j_g`) to
   tracer/cell centers via `grid.interp`.
2. Rotate model components into geographic components using the rotation
   coefficients `CS = cos(alpha)`, `SN = sin(alpha)`:
   - `u_lambda = u*CS - v*SN`
   - `v_phi    = u*SN + v*CS`
   (i.e. apply rotation matrix `R = [[CS, -SN], [SN, CS]]`).
3. For each geographic component, take model-x and model-y finite
   differences (`grid.diff / dxC`, `grid.diff / dyC`), then interpolate
   the gradients back to centers.
4. Rotate the gradient *direction* again with the same `R`:
   - `d_/dlambda = gx*CS - gy*SN`
   - `d_/dphi    = gx*SN + gy*CS`

**Key insight that drives the test design:** the two rotations together
are exactly `R . J_model . R^T`, the proper orthogonal rotation of the
gradient tensor. I verified this algebraically. This matters because:
- It gives **closed-form analytic targets** for synthetic data.
- The **trace** (`du_lambda_dlambda + dv_phi_dphi` = divergence) and the
  **antisymmetric part** (`dv_phi_dlambda - du_lambda_dphi` = vorticity)
  are **rotation invariants** — equal to their model-frame counterparts
  regardless of `CS`/`SN`. These give truth-free checks valid even on the
  curvilinear LLC grid.

#### Synthetic fixtures (answers known exactly)

**Decision (user):** the synthetic grid **mimics the 13-face LLC
topology** — same `face_connections` (`grid.set_xgcm_grid`,
`use_connections=True`) and the comodo `axis`/`c_grid_axis_shift` attrs
from `get_raw_data.py`, but with **uniform** metrics `dxC = dyC = d` and
**spatially constant** `CS`, `SN` so the answer stays analytic. Dims:
`face, i, i_g, j, j_g`; `periodic=False`. Use linear velocity fields in
the per-face model coordinate, placed at the correct staggered points:
- `u = a*x + b*y`, `v = c*x + d*y`.

Because centered differences and linear interpolation are *exact* for
linear fields on a uniform grid, each face's **interior** result is exact
to machine precision. The expected interior outputs are the entries of
`R . J_model . R^T` with `J_model = [[a, b], [c, d]]`. The boundary ring
of every face (halo-exchanged via `face_connections` / `boundary='fill'`)
is excluded from comparison, so the cross-face connections do not
contaminate the analytic check while the topology is still exercised.

Reasoning for choosing linear fields + uniform grid + constant rotation:
it eliminates all truncation error and curvature, so any discrepancy is a
real bug, not discretization noise.

#### Test cases

A. **Derivative values, rotation off (`CS=1, SN=0`).** Rotation is the
   identity, so outputs reduce to the plain model gradients. Expect, on the
   interior: `du_lambda_dlambda=a`, `du_lambda_dphi=b`,
   `dv_phi_dlambda=c`, `dv_phi_dphi=d`. Directly validates derivative
   magnitudes and the `/dxC`, `/dyC` scaling.

B. **90-degree rotation (`CS=0, SN=1`).** `R(90).J.R(90)^T = [[d, -c],
   [-b, a]]`. Expect `du_lambda_dlambda=d`, `du_lambda_dphi=-c`,
   `dv_phi_dlambda=-b`, `dv_phi_dphi=a`. Validates the sign conventions of
   both rotations (the part most prone to error).

C. **Rotation-only, constant field.** Constant `u=U0`, `v=V0` with an
   arbitrary constant angle (e.g. 45 degrees). All gradients must be zero
   everywhere (gradient of a constant), confirming the rotation machinery
   introduces no spurious gradients.

D. **General angle, parametrized.** Sweep `alpha in {0, 30, 45, 90, 137}`
   with the linear field and assert outputs equal `R.J.R^T` analytically.
   Single parametrized test subsuming A and B and exercising arbitrary
   rotation.

E. **Shape / coordinate contract.** All four outputs live on tracer
   centers (`i`, `j`), preserve input dims/shape, and carry no `i_g`/`j_g`.
