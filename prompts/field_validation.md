# Field-validation notebooks: one end-to-end pipeline notebook per subset

## Goals

Build a set of validation notebooks, one per calculated-field subset, at::

    notebooks/notebooks_field_validation/{subset}.ipynb

Each notebook shows the COMPLETE end-to-end pipeline for every final field
in its subset: the raw inputs, the shared intermediate calculations, and
the final fields — with standardized maps, PDFs, depth diagnostics
(DEPTH), and a placeholder for field-specific literature validation.

Notebooks are organized by SUBSET (not per field) because fields within a
subset share raw inputs and intermediates (e.g. ``stratification``:
Theta/Salt → sigma0 → {MLD, N², ml_heat_content}).  Shared intermediates
are computed once; their diagnostics repeat wherever needed so each
field's pipeline reads standalone.

**kinematic_surface** (raw: U, V, [YC])

- coriolis_f: YC → f — CF.coriolis_parameter
- rossby_number: U, V → J → ζ; YC → f → ζ/f — CF.rossby_number

**frontogenesis_surface** (raw: U, V, Theta, Salt, Eta)
- frontogenesis_tendency: (U,V → J) + (Θ,S → b → ∇b) → F(u,v) — CF.frontogenesis_tendency
- ug, vg: Eta → ug, vg — CF.geostrophic_velocity

- frontogenesis_ageo: F(u,v) − F(ug,vg) — SS.compute_frontogenesis (inline)
- Wstar: J + ∇b + f → W* — CF.modified_okubo_weiss

**surface_wind** (raw: oceTAUX, oceTAUY, [oceQnet])
- oceTAUX/oceTAUY channels: raw τ → rotated τ_east/τ_north — CF.geographic_wind_stress
- wind_stress_curl: τ → curl — CF.wind_stress_curl
- ekman_pumping: curl + f → w_E — CF.ekman_pumping
- u_ekman/v_ekman: τ_east/north + f → transport — CF.ekman_transport

**native_fields_surface** (raw: Theta, Salt, Eta, W; computed: U, V)
- U, V: staggered U,V → u_east, v_north — CF.geographic_velocity

**vertical_shear** (DEPTH; raw: U, V, Theta, Salt)
- vertical_shear: U, V → uz, vz → |S| — CFAD.vertical_shear_magnitude
- Ri: (Θ,S → ρ → N², floored) + (uz,vz) → N²/S² — CFAD.richardson_number

**mixing_parameters** (DEPTH; raw: U, V, Theta, Salt, YC)
- Fr: speed + N + MLD → Fr — CFAD.froude_number
- Ro: U,V → J → ζ/f — CF.rossby_number
- Bu: (Ro/Fr)² — CFAD.burger_number
- R_ib: N² (floored) + f + |∇b|² → R_ib — CFAD.balanced_richardson_number

**ertel_pv** (DEPTH; raw: U, V, W, Theta, Salt, YC)
- ertel_pv{,_vertical,_tilt}: J + f + (b → b_x,b_y,b_z) + (uz,vz) + W_c

- Widest dependency chain in the project; columns will need grouping
  (see template note).

**buoyancy_fluxes** (DEPTH; raw: U, V, W, Theta, Salt)
- uB/vB/wB: (u_east,v_north,W_c) × b — CFAD.advective_buoyancy_fluxes

**energetics** (DEPTH; raw: Theta, Salt, YC)
- KE: ½(MLD·|∇b|/f)² — DS.compute_energetics (INLINE — see
  Clarification 4) using MLD, ∇b (NG two-step), f

Key processing operations to flag in every Section 0 table: land/halo
masking (hFacC == 0; gradient halo rim), staggered→tracer interpolation
(U at i_g, V at j_g, W at k_l), CS/SN grid rotation, native-grid
differentiation (NG), depth selection/averaging (sfc / z25m nearest-k /
MLD extraction / MLD thickness-weighted mean — ``depth_strategies.py``),
face→latlon stitching (``faces_to_latlon``), global downsampling for
Row A, and the anomaly conventions (σ₀ = ρ−1000; b anomaly-based).

## 3. Data loading strategy

Two clearly distinguished routes:

**Route A — 2D products, loaded directly.**  Final-field global maps and
regional 2D subsets come from the produced zarr stores via
``GlobalZarrDatasetReader.get_channel_snapshot(t, channel)`` with
coordinates/land mask from ``GlobalGridZarrReader`` (lon, lat,
land_mask).  Row A (global) downsampled ``[::12, ::12]``; regional rows
sliced from the rectangular grid by named-region bounding boxes
(regions module, Section 5).  Raw/intermediate 2D fields for the SURF
figures are computed LIVE in the notebook from the OSN/S3 snapshot via
``calculate_fields`` (cheap for 2D; guarantees the intermediates match
the code being validated).  ⚠ Existing stores were generated
PRE-migration; see Clarification 1.

**Route B — 3D data, via the tiles workflow ONLY.**  Never load global
3D DEPTH data in a notebook.  All vertical profiles, cross-sections, and
any 3D intermediate diagnostics come from single-face 720×720×51 tiles
(≈1400×1400 km, full water column) obtained through
``dbof.tiles.tile_utils``.

## 4. Tiles workflow (existing capability and gaps)

Existing (reuse as-is):

- ``tile_mapping.rect_ij_to_tile(i, j) → TileInfo`` — 432 fixed tiles on
  the rect grid; guarantees single-face, chunk-aligned 720×720 slices
  (face idx + face-local j/i slices).
- ``tile_utils.latlon_to_rect_ij(lon, lat)`` — geographic tile selection.
- ``tile_utils._load_grid_for_tile`` — tile-extent grid (XC, YC 2D; Z 1D;
  hFacC for the land mask; metrics available from the grid store).
- ``tile_utils._load_tracers_for_tile`` — lazy S3 read of requested vars
  for one face, sliced to the tile, dims (face=1, k=51, j=720, i=720).
- ``TILE_PROPERTIES`` registry + ``compute_tile_property`` +
  ``_build_output_dataset`` (XC/YC/Z coords, provenance attrs, NetCDF)
  + ``run()`` end-to-end (by rect pixel or lon/lat), with QA plot.

Current registry limitation: ``TILE_PROPERTIES`` = {density,
temperature, salinity} and ``vars_needed`` covers tracers only.  Minimal
eventual extensions (NOT built yet):

1. A ``raw_3d`` tile property (or per-variable entries) for U, V, W —
   ``_load_tracers_for_tile`` already accepts arbitrary ``vars_needed``;
   the gap is registry entries + handling staggered dims (i_g/j_g/k_l)
   at the tile boundary (one extra edge column/row or accept N−1).
2. A "tile ds_merge" helper that merges tile tracers + tile grid and
   builds a LOCAL xgcm grid (``use_connections=False`` — a single face
   has no face_connections).  Consequence: gradient-based fields are
   edge-contaminated in a ~3-cell rim (same as the synthetic-test
   EDGE_MARGIN); notebooks trim the rim before plotting.  Interior of a
   720² tile is unaffected.
3. Optionally: register final-field tile properties (N2, MLD, Ri, ...)
   pointing at the existing CFAD functions — they are dimension-agnostic
   and lazy, so ``compute=`` wiring is one line each (the density entry
   already demonstrates the pattern with
   ``calculate_fields.potential_density_anomaly``).

Answers to the specific tile questions:

- Region/tile specification: by ``lon/lat`` (preferred for notebooks) or
  rect pixel; tile dims are FIXED at 720×720×51 on one face — a tile
  SAMPLES a validation region, it does not cover it.  Each region
  therefore gets its own representative tile (Section 6).
- Raw variables per subset tile: stratification/frontal Θ,S;
  vertical_shear/kinematic/mixing +U,V; ertel_pv/buoyancy_fluxes
  +U,V,W; energetics Θ,S (+YC from grid).
- Intermediates/finals from tiled data: via the same ``calculate_fields``
  / ``calculate_fields_at_depth`` functions on the tile ds_merge (they
  are dimension-agnostic; proven by tests/test_calculate_fields.py).
- sfc / z25m / MLD diagnostics from ONE tile: yes — k=0 slice, nearest-k
  to 25 m (``VH._nearest_k_to_depth``), and MLD extraction
  (``depth_strategies`` / ``VH._extract_at_mld``) all operate on the
  same tile volume.  This also cross-checks Route A: the tile's suffix
  slices should match the corresponding region of the 2D product maps.
- Metadata: retained (XC/YC/Z coords, hFacC mask, attrs) by the existing
  ``_build_output_dataset`` pattern.
- Coverage: one tile per region; profiles AND cross-sections both come
  from the same tile (Section 6).

- Row C — Atlantic sector, Southern Ocean: ~20°W–20°E, 65–40°S
- Row D — eastern tropical Pacific: ~140–90°W, 5°S–5°N

Representative DEPTH tiles (one per region; selected by lon/lat through
``latlon_to_rect_ij``; exact tile idx recorded in the notebook):

- B: Gulf Stream tile near (−60°E, 37°N) — strong fronts, deep winter
  ML; best all-round tile for shear/PV/frontogenesis.
- C: ACC tile near (0°E, −52°N) — deep MLD, strong eddies.
- D: equatorial tile near (−110°E, 0°N) — shallow thermocline, EUC
  shear; note f→0 makes Ro/R_ib/W*/ekman NaN-heavy here (expected;
  document rather than avoid).

Figure 3a (profiles): 10 columns per regional tile, selected by seeded
RNG (``numpy.random.default_rng(42)``) over ocean-only (hFacC[0]>0),
rim-trimmed (≥3 cells) tile pixels; plus bold tile-mean profile.  Same
10 locations reused across all fields in a notebook (comparability).

Figure 3b (cross-sections): RECOMMENDATION — one consistent definition:
the tile's central meridional strip, i.e. latitude–depth section
averaged over the middle third of the tile's i-range (~±240 px ≈ 500
km of longitude), latitude span = tile extent (~13°).  Same definition
for all three tiles → region-specific only through tile choice, not
through bespoke section logic.  A basin-scale section is impossible
from one tile; if ever needed it becomes a row of adjacent tiles
(future extension, out of scope).

Recommended single representative region if only one tile is budgeted
per notebook run: Row B (Gulf Stream tile) — every field in every
subset is dynamically active there; C and D tiles then serve as
optional extra rows.

## 7. Notebook template (shared, section-by-section)

Every notebook follows this skeleton; DEPTH-only parts marked [D].

0. **Header + provenance**: subset, pipeline, date (20121109T12 — the
   only DEPTH date; Clarification 2), run_id/store used, git commit,
   link to Fields.md row and to this plan.
1. **Section 0 — Field & dependency table**: the 5-column table (Field /
   Units / Equation / Equation location in code / Dependencies) covering
   raw → intermediate → final, plus the processing-operations checklist
   (masking, interpolation, staggering, rotation, differentiation,
   downsampling, vertical selection, unit conversion) with a
   yes/no/where note per operation.
2. **Data loading**: Route A reader cells (2D products + grid + land
   mask) and, [D], Route B tile cells (one per region).  Explicit
   printout of shapes, coords, and the date/iteration confirmation.
3. **Shared intermediates**: compute the subset's shared intermediates
   ONCE (e.g. sigma0, b, J, ∇b, N², MLD) from raw inputs, with a short
   sanity printout (min/max/units) per intermediate.
4. **Sections 1–X — one per final field**, each containing:
   a. one-paragraph pipeline description (raw → intermediate → final)
      + equation;
   b. **Figure 1 (maps)**: `pipeline_grids` scaffold, columns =
      dependency order, rows = domains A–D;
   c. **Figure 2 (PDFs)**: same scaffold, PDF panels; conventions
      stated in-figure (NaN/mask removal: yes, land + halo rim;
      physical filters if any: stated per field; bins: shared per field
      across regions; y-axis: probability density; log-scaling: log10-x
      for ∝-squared fields, log-y where stated);
   d. [D] repeat Figures 1–2 per suffix: separate complete figures for
      `_sfc`, `_z25m`, `_mld` (and `_mld_mean` where meaningful) — no
      combined overcrowded figures;
   e. [D] **Figure 3a/3b**: profiles + cross-section from the regional
      tiles (skip for inherently-2D fields: MLD, ml_heat_content,
      gradeta2, ug/vg, wind/ekman — note instead);
   f. **Literature placeholder** (Figure 3 surface / Figure 4 depth):
      fixed structure = (left) our diagnostic rendered by a callback,
      (right) supplied literature .png, (below) short discussion of
      similarities/differences/physical plausibility.  Diagnostic type
      deliberately unspecified until reference is provided; the
      `literature_comparison` module accepts any renderer.
5. **Cross-references**: links to sibling notebooks for
   already-validated dependencies (MLD → stratification; σ₀/b →
   frontal_structure_surface; rotation/Jacobian machinery →
   kinematic_surface).
6. **Summary cell**: pass/fail-style checklist (units sensible, maps
   physically structured, PDFs plausible, suffix ordering sensible,
   guard-style uniqueness check) mirroring
   `dev/verify_subsets_real_data.py` stats.

Template accommodations (subset-specific complications):

## 9. Ambiguities, inconsistencies, and missing metadata found

- The produced zarr stores predate the field migration: buoyancy-family
  channels are legacy-scaled, the density channel is σ₀+1000-style, and
  buoyancy is non-anomaly.  Loading finals from them while computing
  intermediates live would show inconsistent pipelines
  (Clarification 1).
- Only one DEPTH date exists (20121109T12); OSN wind covers only
  2011-11-01–2012-07-15, so surface_wind at that date requires the
  LLC_SURF S3 store path (present for 20121109T12? — verify).
- ``field_cmaps.yaml`` covers output channels but NOT intermediates
  (rho_theta, b, b_x/b_y, J components, uz/vz, W_c, curl τ before
  scaling) — entries must be added for the dependency columns.
- KE and frontogenesis_ageo are dispatcher-inline (no CF/CFAD function)
  — table "equation location" cites dispatcher functions; consider
  promoting KE to CFAD (Clarification 4).
- ``mixed_layer_depth_DI`` exists but has no output channel — worth one
  comparison panel in stratification.ipynb (MLD vs MLD_DI) as a bonus
  diagnostic.
- `llc_plotting.plot_pdf_dask`/`plot_log_pdf` are rudimentary
  (hist-based, no region/bin policy) — superseded by `pdfs.py` rather
  than extended, but kept for raw-face QA.
- Tile registry lacks U/V/W entries and a merged-grid helper (Section 4

- ``surface_subsets`` OSN `log_gradb` channel: confirm whether it is an
  output channel anywhere (it appears in sampling docs, not in
  subset_definitions) — if not, validate under gradb2's section.
